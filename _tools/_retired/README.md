# 退役したツール

## check-hub-drift.py（2026-08-03 退役）

**②' と ③ をバイト単位で比較する検査。前提が成り立たなくなったため退役。**

③ の HTML は ②' のミラーではなく**派生物**で、取り込みまでに 3 つの変換が入る:

1. SharePoint 汚染の除去（`sanitize`）
2. `<title>` の復元（`og:title` もしくは ③ の既存値から）
3. `inject` による共通パーツの置換
   （②' はマーカー無しで直接埋め込み、③ はマーカー付き）

このため生バイト比較は**常に赤**になり、実際に 30 件を誤って drift 扱いしていた
（`sitemap.xml`、改行コードだけ違う SVG、inject 位置が違う HTML を含む）。
「赤いのに正常」は判断を鈍らせるだけで、検査として機能しない。

### 代わりに何が守るか

- **`hub.py publish` が `import` を内包**し、②'→③ の唯一の経路になった。
  手コピーの余地が無くなったので、両者のずれ自体が起きにくい
- **内容の健全性**は汚染検査・`inject --check`・`gen-sitemap --check`・
  不変条件検査が見る（`hub.py check` の 5 検査）
- **③ の勝手な追加**は pre-commit が「②' に対応物が無い」で止める
- 最終的な歯止めは CI（`hub-validate`）とブランチ保護

### 復活させるとしたら

生バイト比較では駄目で、「②' から同じパイプラインで再構築した期待値」と比較する
必要がある。ただしそれはパイプラインを二重に持つことになり、変更のたびに
検査側も直す羽目になる（2026-08-02 に pre-commit の照合で 5 回失敗した）。
`hub.py` を唯一の経路に保つ方が安い。
